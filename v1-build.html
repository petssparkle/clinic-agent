V1 Build Playbook · Continuous build mode · Founder + Claude Code

Ship the Cowork MVP — alongside Claude Code, today.

This is the action playbook for a non-developer founder (Mahmoud) + one engineer co-founder (Belal) building the MVP right now with Claude Code. No multi-week sprint plan — just the accounts to sign up, the credentials to hand over, and the 11 stages the code moves through. Continuous build mode — ships when the 11 stages are green and 1–2 beta customers onboarded successfully.

00📋 Pre-Flight Checklist — Set Up TODAY (~1 hour, founder work)

This is the founder's job — not Claude Code's. Get every account created, every credential copied into a shared 1Password vault, and the Meta App filed for review. The Meta review takes 3–10 business days, so it's the slowest dependency — file it first. Claude Code can build everything else in parallel while you wait.

4. Meta App Creation (~30 min — file TODAY to start the review clock)

This is the single slowest dependency in the entire build. Standard review takes 3–10 business days. File it today even if you don't need the credentials for a week.

  • Go to developers.facebook.com/apps → Create App
  • Type: Business. Name: Cowork. Log in as Belal.
  • Add 3 products: WhatsApp Business Platform · Instagram (Messaging API) · Messenger Platform
  • From Settings → Basic: copy App ID and App Secret — save these in the vault.
  • Make up a Verify Token (any random 20+ character string, e.g. cowork_verify_xK9p2mZqRt8aB3wY) — save it. This is your choice; Meta just echoes it.
  • Add a 1024×1024 app icon (Figma or Canva → export a teal-on-white "C" mark).
  • Submit each of the 3 products for App Review. Fill the form for each:
    • Business description: "Unified inbox for SMBs to manage WhatsApp, Instagram, and Messenger conversations from one screen, with an AI assistant that auto-replies using a business-curated FAQ library."
    • Use cases: customer support, appointment booking, lead capture across Meta surfaces.
    • Demo video: 60–90s screen recording of the inbox (record once Stage 3 is done — until then save a draft).
  • Standard review: 3–10 business days. File today. Build around it.

01What we're shipping in V1

Four pillars. Every stage maps back to one of them. If a feature doesn't map, it's V1.1.

Pillar 1 · Unified Inbox

  • WhatsApp + Instagram + Messenger in one view (TikTok = V1.1)
  • Inbound webhook per channel · send replies from one UI
  • One thread per customer across all channels
  • Private notes · @-mentions · quick-reply templates

Pillar 2 · AI Chatbot

  • Fixed-reply mechanic — bot only sends what the business wrote
  • Claude API classifies intent on every inbound message
  • FAQ Library editor + Setup Wizard to populate it
  • Human handoff when intent doesn't match

Pillar 3 · Calendar

  • Native booking (working hours, slot rules, no double-booking)
  • Bot offers free slots on booking intent → customer picks → appointment created
  • Pre-appointment reminders (timing set by business)
  • Email notification to owner on every booking

Pillar 4 · Mini CRM

  • Every inbox message auto-pulled into a Contact record
  • Tags (auto + custom) · private notes · status
  • Unified conversation history per contact, across channels
  • Custom Follow-Up Rules + basic analytics
That's the whole V1. 22 features around 4 pillars. Anything not here is V1.1 — no exceptions.

03The 11-stage continuous build

Each stage is built by Claude Code, end-to-end, in continuous mode. No weekly schedule — we move to the next stage when the current one is green. Each stage tells you the goal, what gets built, the credentials Claude Code will ask for, and the "done when" gate.

Stage 1
Foundations & Schema

Goal: a deployed Next.js app with a multi-tenant Postgres schema and working auth.

  • Scaffold Next.js 14 + Tailwind + shadcn + Prisma
  • Apply the V1 Prisma schema (Workspace, User, Contact, Conversation, Message, Note, Reply, Tag, BookingSlot, Appointment, Rule) — all FKs to workspaceId
  • Wire Clerk Organizations → new signup auto-creates a Workspace
  • Protected /dashboard route

Credentials you provide: DATABASE_URL · DIRECT_URL · Clerk publishable + secret keys.

Done when: sign-up → workspace created → land on empty /dashboard. DB has all V1 tables.

Stage 2
WhatsApp End-to-End + Idempotency

Goal: a real WA message hits a webhook, lands in the DB as a Contact + Conversation + Message, and the dashboard can send a reply back.

  • Webhook route for WhatsApp Cloud API (GET verify + POST ingest)
  • ingestMessage() service — find-or-create Contact + Conversation, insert Message, idempotent on Meta's message ID
  • Outbound send wrapper for the Graph API
  • If Meta hasn't approved yet — use Meta's developer sandbox test number to keep moving

Credentials you provide: Meta App ID + App Secret · Verify Token · WhatsApp Phone Number ID · Access Token. (Skip live test if Meta App Review isn't back yet — use sandbox.)

Done when: text the test WA number from a real phone → message appears in the DB attached to a fresh Contact + Conversation.

Stage 3
Unified Inbox UI + IG + Messenger Connectors

Goal: the dashboard shows all conversations across all 3 Meta channels in one view, and replies send back through the right channel.

  • Conversation list (left rail) · open thread (right pane) · reply box
  • Channel-aware badges so the agent sees which channel each message arrived on
  • Instagram + Messenger connectors plug into the same channel-connector interface as WhatsApp
  • Cross-channel Contact merging (one Contact, multiple channel handles)

Credentials you provide: IG Business Account ID · Page Access Token (Messenger).

Done when: a customer DMs us on IG → same Contact card as their existing WA Contact, both threads visible in one timeline.

Stage 4
AI Chatbot Engine

Goal: every inbound message gets classified by Claude against the workspace's FAQ library and auto-replies with the matching fixed reply, or hands off to a human.

  • Intent classifier service calling the Claude API on every inbound message
  • If matched → fetch the workspace's Reply for that intent + language, send via the channel connector, mark message as sentByAI
  • If no match → don't reply, flag conversation as HANDED_OFF, notify the owner
  • Log every classification so we can tune the prompt later

Credentials you provide: ANTHROPIC_API_KEY.

Done when: load the test WA number with a 10-reply FAQ library, fire 10 inbound messages — at least 8 get the right auto-reply, the other 2 trigger HANDOFF.

Stage 5
Setup Wizard + FAQ Library + Vertical Presets (highest-leverage stage)

Goal: a non-technical business owner can go from signup to "bot is replying" in under 60 minutes, without any help.

  • Multi-step wizard — business name → vertical → working hours → services → tags → FAQ replies
  • FAQ Library editor — list of intents, click to edit reply, multi-language fields
  • Vertical presets (clinic · retail · education · auto · real estate) — pre-populate the FAQ library with sane starter replies
  • Server-side validation on every submitted field

Credentials you provide: none new — uses Anthropic + DB from prior stages.

Done when: Mahmoud (non-engineer) can complete the wizard for a fake clinic in under 60 minutes without help.

Stage 6
Calendar + Booking + Reminders

Goal: a customer DMs "I want to book", the bot offers slots, the customer picks one, an appointment lands in the DB, the owner gets an email, and a reminder fires before the appointment.

  • Working-hours editor per workspace
  • Slot generator (background job, nightly, 30 days ahead)
  • New BOOK intent → bot replies with next 5 free slots → customer picks → appointment created → slot marked booked → owner email
  • Reminder job (hourly) — fires pre-appointment reminders on the right channel

Credentials you provide: RESEND_API_KEY · Inngest Event Key + Signing Key.

Done when: end-to-end booking flow works on a real phone: DM → pick slot → appointment exists → reminder arrives 24h before → owner email confirmed.

Stage 7
Mini CRM + Tags + Custom Follow-Up Rules

Goal: every conversation rolls up to a Contact with full history, and the business can set no-code follow-up rules ("if customer asked price and didn't book in 24h, send win-back reply X").

  • Contact detail page — unified timeline of messages, bookings, notes, tag changes
  • Tag system — manual + auto-tag rules (source-based, intent-based)
  • Rule Builder UI — pick a trigger, a delay, and a reply from the FAQ library
  • Rules engine job — evaluates enabled rules against eligible conversations every 15 min

Credentials you provide: none new.

Done when: a rule like "no booking within 24h after price intent → send win-back reply" fires correctly within 16 min of becoming eligible.

Stage 8
Notes + Quick Replies + Business Hours + Analytics (FEATURE FREEZE)

Goal: close out the last UX features and lock the V1 surface — no new scope after this stage.

  • Private notes on conversations (internal-only, hidden from customer)
  • Quick replies — per-agent text shortcuts that paste saved snippets into the textarea
  • Business-hours / out-of-office auto-reply — outside hours, send a custom OOO message instead of running the classifier
  • Basic Analytics dashboard — 6 counter cards: messages answered, bookings made, conversion rate, top-requested items, channel performance, handoff cases

Credentials you provide: none new.

Done when: all 22 V1 features check off · the Setup Wizard is the only path a new business needs.

Stage 9
Stripe Billing + Plan Gating + Trial + Demo Data

Goal: real money can be charged, plans gate features, and new signups see a believable demo of the product on first load.

  • Stripe subscriptions ($15 / $59 / $199 / Custom) · webhook handler · 14-day trial logic
  • Plan gating — features visible/usable based on workspace plan
  • Contact Packs one-time purchase flow
  • Demo data seeder — every new workspace gets a "demo" Contact + Conversation so the empty state is never empty

Credentials you provide: Stripe Secret Key + Webhook Secret · Stripe price IDs for each plan.

Done when: a real Stripe checkout completes, the webhook updates the Workspace plan, and the trial countdown is visible on the dashboard.

Stage 10
Stabilize · Security · Marketing Site · Code Hygiene

Goal: production deploy on a custom domain, observability wired, security audit done, marketing site live.

  • Vercel production deploy locked to main · PR previews enabled · custom domain (cowork.app) live with SSL
  • PostHog tracking key events · Sentry catching errors · BetterStack uptime monitoring
  • Security pass — rate limits on webhooks, RLS-style scoping verified on every query, secrets rotated, .env.example documented
  • Marketing site — landing page, pricing, privacy/terms, signup CTA
  • Type-check + lint clean · Playwright e2e covering: signup → wizard → receive WA → bot replies → book → confirm

Credentials you provide: Vercel (GitHub connect) · PostHog project key · Sentry DSN · BetterStack token · custom domain DNS access.

Done when: production URL responds, key flows tracked in PostHog, Sentry shows zero P0 errors, marketing site is live.

Stage 11
Private-beta Dry-Run + Final Polish

Goal: 1–2 friendly real businesses run through the Setup Wizard end-to-end and use the product for real conversations. Every UX papercut they hit gets fixed.

  • Onboard 1–2 friendly customers (not paying yet) — watch them go through the Setup Wizard with no help
  • Fix every friction point surfaced — no new features, only the papercuts
  • Ops runbook — how to rotate the Meta token, re-issue the Anthropic key, roll DB credentials, manually retry a stuck webhook
  • 48-hour cron sanity check — reminders, rules, slot generator all firing cleanly with zero errors in Sentry

Credentials you provide: none new — just the friendly customers' real Meta credentials when they sign up.

Done when: at least one friendly business successfully runs Wizard → live chat → real booking on their own, AND the launch checklist (§04) is fully ticked.

Continuous build mode. Stages move forward when the "Done when" gate is green — no calendar. After Stage 11, we open to paying customers.
